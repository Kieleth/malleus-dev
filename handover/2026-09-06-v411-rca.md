# RCA: iteration 10 (v4.11), the type set was never a reach filter, 2026-09-06

Overseer session. The change is one module, `paper-v4/experiment-v4/type_set_closure.py`, with six tests (RED 6d4fba3, GREEN 8754b44) and no cell run; the rerun is the check applied to every frozen cell's surface, contract and sets. Evidence: the frozen public files of runs 08 to 21, run-20's private query result, run-21's launch log. The reading is quoted nowhere.

## What happened

Run-21's binding, frozen at acceptance, was refused at execution: an AnalyticalMethod record reached through the Method case had no projection because its type was in no set (E-0196). The correction was the evaluator's, made before any row existed. Iteration 10 moves the refusal to bind time. Writing the test for run-20, whose sets I expected to be closed, the check named three omissions with records behind them, and the executor had never refused run-20.

## Root cause: two rules in two places, and a set that governs neither

Reach is the facade's: `graph.query(type)` returns a type's records and its subtypes'. Projection is the binding's: the executor builds one map of type to fields from every case in every question, and projects each reached record by its own type. The evaluator's per-question set sits between the two and constrains neither. A set that lists Method reaches every Method subtype in every question; the row projects by the subtype's own fields as long as the subtype is named anywhere in the binding; and only a subtype named nowhere trips the refusal. Run-21 tripped it because its producer minted one Method subtype and the evaluator, translating run-20's judgement, listed the parent alone. Run-20 never tripped it because GeophysicalModel was named in CQ-03 and SoftwareTool in CQ-01, so both projected everywhere.

Measured over the frozen cells: seven of twelve cells with frozen sets were not closed per question (runs 08, 09, 10, 12, 13, 15, 20), five were (runs 11, 14, 16, 19, and 21 after the amendment). In run-20, CQ-01 carries 6 GeophysicalModel rows its set did not name; CQ-03 and CQ-04 carry 8 SoftwareTool rows each their sets did not name.

## Why nobody saw it

The review judges rows on the reading, so a reached row from an unlisted subtype was judged like any other and supported or not on its block. The type-set notes described intent ("GeophysicalModel only in CQ-03 and CQ-04"), and nothing compared intent to reach. The row counts per question were read against each other across cells and were comparable, because the reach followed the same rule in every cell. The one place the discrepancy could surface was a subtype named nowhere, which needed a surface coarse enough for that: run-21's.

## The fix, and the one not taken

Taken: the closure check at bind time. The set must list every surface subtype of every type it lists, read from the contract's `subClassOf` facts, or the binder refuses with a typed reason and the evaluator corrects the set before phase two. After it, the set states what the question reaches. One function, one place, and the executor's rule becomes a second net rather than the first.

Not taken: making the executor filter reached records by the listed types, which would turn the set into a reach filter. It would remove rows from seven frozen cells' shapes and change every cell's comparability, which is Luis's to decide, and it would make the set a stricter instrument than the evaluator ever used it as. The closure check keeps the executed rule and fixes the description.

## What it changes in the records

No row, no label, no count moves. The type-set notes of runs 08, 09, 10, 12, 13, 15 and 20 carry "left out" or "only in" sentences that did not hold where a listed parent had an unlisted subtype; E-0198 corrects them in one place rather than editing seven frozen notes. Run-20's E-0189 sentence, "the EarthFeature subtypes named one by one, the parent and the two catalogue types in no set", holds as written: the parent was not listed, so no subtype was reached through it; the discrepancy in run-20 is under Method, not EarthFeature.

## Lesson

A partial read, twice. The acceptance note reasoned about the binder from another note; the test expectation reasoned about run-20's closure from its note. Both were one docstring or one function call from the fact. The check is cheap because the contract already carries the closure; the loop paid for it with a refused binding and a wrong test expectation, both recorded.
