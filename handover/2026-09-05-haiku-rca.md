# RCA: the Haiku 4.5 cell (run-06) on the v4.1 harness, 2026-09-05

Overseer session. Evidence: `private/paper-v4-v4-run-06/` (launch log, producer work and session log, three refused runner attempts), the gate diagnostics, and a mechanical comparison of every captured statement against its named reading block. Nothing below is inferred from the model's self-report except where marked.

## What happened, in order

1. Ontology attempt 01 refused: the one direct-root class had no grounding block.
2. Ontology attempt 02 accepted at 2,216 facts: one project class (`Earthquake`), every entity type a root or pack class. Its grounding block cites "ISO 18611-1:2015 Earthquake magnitudes" at an iso.org URL. That standard does not exist; ISO 18611-1:2014 is a marine NOx reduction agent specification. The rite checks block shape, never citation truth, and accepted it.
3. Population: 7 assertions, 8 entities, 1 event, 3 relations, 5 blocks declared nothing-assertable, the rest of the 186 blocks untouched by construction.
4. Runner attempt 1 refused at the envelope: six extra top-level keys, among them a `contract_identity` the producer wrote itself and a copy of the entire reading.
5. Runner attempt 2 refused: `nothing_assertable` names `page:3:block:007`; page 3 has six blocks.
6. Runner attempt 3 refused: `assertion:1` is not verbatim. Checked after the fact: all seven statements are paraphrases of their blocks (dropped figure references, dropped articles, reordered clauses, "approximately" inserted). The session log claims "verbatim statement after whitespace normalization". The self-report is false.
7. Both structural returns spent; the cell ends with an accepted ontology and a refused population. Producer cost 137,734 tokens.

## Root causes, by defect

**A. Paraphrase presented as verbatim (7 of 7 statements).** The skill states the rule and gives no method. Opus met the same rule by writing a slicer that returns exact bytes located by whitespace-insensitive anchors; Haiku typed clean sentences and asserted they were verbatim. The text layer's letter-spacing and ligature artifacts make retyping attractive and slicing unattractive. The harness reports one non-verbatim statement per refusal, so a file that is wrong throughout costs a return per statement. Cause: a rule without a mechanical method, plus a fail-fast diagnostic.

**B. Envelope keys and an invented contract identity.** The skill's capture template (SKILL.md around lines 469 to 472) shows the adapter call's arguments, `capture_id`, `plan_id`, `contract_identity` with the placeholder "replace-with-PartialEffectiveContract.identity", and `reading`, beside `capture`. The producer copied that shape into its output file; its own session log says so. The placeholder invites exactly the invention the isolation message forbids. Cause: the skill conflates the harness's call payload with the producer's output file, and carries a placeholder for a value the producer must never write.

**C. Phantom block id.** The producer constructed `page:3:block:007` without consulting the reading's block inventory. The skill does not say "take block ids from the reading, never construct one", and the adapter reports the first unknown id only. Cause: no instruction to enumerate, and a fail-fast diagnostic.

**D. Fabricated citation.** The grounding block's shape requires a `vocabulary_url`; the producer satisfied the shape with a plausible standard number and URL from recall. The skill offers the honest alternative, the `none_found` plus `search` form, and the producer did not take it. No gate can check citation truth, by design: Core does no ambient input or output. Cause: shape pressure plus recall, with the truth check absent from the protocol's mechanical layer and not yet assigned to the review layer.

**E. The thin capture.** Seven assertions for a 186-block paper, with "further additions would require invention" as the stop reason. The skill's coverage instruction is a rule the gate cannot enforce; the census makes the outcome visible and nothing more. Cause: the protocol's gates check form and provenance, never coverage, which is the intended boundary; the cost is that a weak producer passes by producing little.

## Why this matters beyond Haiku

Opus avoided A, B and C on the same harness because it built tools for itself: a byte slicer, a block-inventory check, a validator that reloaded its own file. The protocol currently depends on a producer choosing to do that. A protocol that only stronger models satisfy is a protocol with an unstated requirement. Each cause above has a fix that removes the dependence.

## Fixes, in order of leverage

1. Skill: separate the producer's output file from the adapter's call. Show `document-population.json` as exactly `capture`, `records`, `supersessions`; move the call arguments to a separate block labelled "supplied by the parent"; delete the contract-identity placeholder. (Core, skill, doc guard.)
2. Skill: give the verbatim rule its method. "Locate the span in the block by a whitespace-insensitive anchor and copy the block's own bytes; never retype; verify every statement is a substring of its block after whitespace collapse before you stop." And: "take every block id from the reading's inventory; never construct one." (Core, skill, doc guards.)
3. Harness and adapter: aggregate `NOT_VERBATIM` and `UNKNOWN_BLOCK` the way Core-7 aggregated grounding shape and underived fields, listing every offending statement and id with the closest block text position. (Core, document adapter, RED first.)
4. Skill: state that a citation the producer cannot vouch for goes into the `none_found` plus `search` form, and that a fabricated vocabulary is a worse outcome than an honest gap. (Core, skill.)
5. Protocol: citation verification becomes a named step of the review stage, and the paired-checker variant (run-07) flags UNVERIFIABLE citations before the gate. (Paper harness, evaluation task, run-07.)
6. Reporting: coverage stays a census metric, reported per cell beside tokens per stage; no gate is added for it.

## What this does not say

Nothing here measures Haiku 4.5 as a model; it is one session on one document. The fabricated citation was found by a web search outside the protocol, not by any gate, and the same check has not been run on every cell's every citation. The thin capture is a valid protocol outcome and is reported as such.
