## The result we still need

Show that an acquisition procedure maintains interpretations as evidence grows:
it revisits earlier conclusions, preserves justified meanings, identifies real
changes and open questions, and supplies usable evidence-linked answers.
Retaining a history or collecting current review receipts does not establish
this result. A scripted test and a model experiment establish different things.

## Proposed dependency order

1. **Freeze one case and its meaning requirements.** Shop proposes a small story
   using existing sources. KGs checks that it can distinguish added information,
   correction, refinement, justified no-change and unresolved meaning where the
   actual evidence warrants them. Do not force every outcome into one story or
   mistake a world-state update for a correction of interpretation. Paper fixes
   the independent assessment and reader obligations. Select exact source,
   schema/runtime and visibility conditions before execution.
2. **Test the machinery on explicit synthetic interpretations.** Compile the
   chosen schema, test readers and missing/stale review refusal, and exercise
   separately selected admission/replay where needed. A supported no-change is
   a valid result. A correction proposal must not mutate accepted state merely
   because review completed. These tests establish representation and workflow
   behavior, not model understanding.
3. **Test actual acquisition in one small controlled model run.** A fresh
   producer receives only the selected evidence stage, schema/procedure and its
   permitted prior interpretations. It does not receive future material, the
   expected answers or an old full-source graph. Review all members of the
   declared small interpretation set at each stage, including earlier completed
   ones. Record what actually changed, why, what did not, and remaining errors.
   A manually planted error is a synthetic stress case, not a model-discovered
   correction. Model, effort, budgets and correction rounds need explicit
   selection before this step.
4. **Transfer immediately to GE-1 in the PDF.** Paper implements the scientific
   reader/representation tests and staged source experiment, using KGs' meaning
   requirements. Transfer the procedure and public interfaces, not Shop's domain
   schema or policies. The body already contains origin and some RC2 argument;
   do not manufacture learning by hiding them. Distinguish reference resolution
   from error correction and scientific corroboration.
5. **Extend by a new semantic difficulty.** GE-2 tests a qualified joint model
   statement; GE-3 tests scoped argumentative support and changing premises.
   Research can proceed in parallel, but broader capture and paper claims wait
   for their own actual results. Do not grow the corpus merely to grow it.

## First-case recommendation after source inspection

Paper, KGs and Shop now recommend the **payment-context case** for the
interpretation question. Shop initially proposed supplier order B as the smallest
mechanics case, then agreed that the fixed-table/context case better tests this
goal. These are not two approved experiments, and owner agreement is not author
execution approval.

In the recommended case, stage one exposes the selected existing historical
table. Stage two retains that same table and adds only its existing prose about
the shared customer, shipment policy and payment-related delay. The table already
contains P1's receipt and its clearing of I1 and I2. Later prose can explain how
the author relates these events, but cannot establish a complete customer account
or grant permission to ship. Overlord inspected these exact rows/passages and
the existing shipment-explanation reader in Shop's isolated checkout.

The useful observations are deliberately different:

- An earlier supported reading is reviewed and remains true: payment receipt
  and invoice clearing are distinct recorded occurrences.
- Previously unavailable context can now be connected: shared-customer scope
  and the author's stated explanation for O2's delay.
- A remaining unknown stays unknown: full-account unpaid status and actual
  shipment authorization are not supplied by these sources.

Actual model outcomes must be assessed as produced. Do not demand a correction
when refinement or no-change is justified; do not script the model's initial
mistake. A planted error is a separately labelled negative control.

Keep supplier order B as the existing mechanics/control reference. Its change
from one to two total units establishes a source-state update under the selected
mapping, not by itself progressive reinterpretation. Neither already-built
history can serve as a first-stage producer input: both contain full context.
The new exposure packets must be separately frozen and access-checked.

Paper's source/code inspection found a concrete local prerequisite. The current
`shipment_explanation._inputs` rereads full retained prose, and
`shipment_read_spec.json` selects the passage roles, rule limit and
account-completeness assumption. Overlord independently inspected that code and
confirmed the full-context/specification dependency. The existing importer also
retains all context before row imports. Reusing that hybrid reader unchanged
would not demonstrate graph-captured contextual meaning or blind staged reading.

Therefore the first cut needs a minimal **Shop-owned representation** of
source-attributed contextual explanation, tested through public compilation and
reader access. Do not build an account/permission engine or mistake the narrative
policy for an active admission rule. Two readers must independently recover the
required distinctions, not merely wrap the same existing interpretation.

The context source contains investigator `purpose` and `disposition` fields.
Keep its original bytes for evidence, but producer exposure must use exact source
text and neutral locators, not those annotations, the read specification or
`source_expectations.json`. Expected meanings belong to independent assessment.
The exposure check must cover schema descriptions, helper code, prompts and
prebuilt graph/history inputs too. Withholding a prose file is insufficient if
another supplied artifact already encodes its conclusions. A generic supplied
representation must not preload the later case-specific customer/policy facts.

## Separate claims and decisive evidence

| Question | Evidence required | What does not establish it |
| :--- | :--- | :--- |
| Can the representation express the distinction? | Contrasting synthetic meanings remain distinguishable by fixed readers, with malformed/ambiguous cases exposed | YAML parsing or a plausible schema description |
| Does the model acquire and reconsider meaning faithfully? | Independently source-grounded assessments of actual staged proposals, including unchanged interpretations and errors | Authored dispositions or a current review receipt |
| Does Malleus preserve accepted revisions? | Actual admitted changes, unchanged prior evidence and reconstruction of the selected earlier/current accepted states | A proposed correction or a graph comparison alone |
| Can another reader use the captured meaning? | Fresh-reader answers with exact supporting paths, omissions and source-access conditions reported | Correct answers recovered by unrestricted rereading attributed to graph structure |

Improvement needs a stated comparison. Hold readers, evidence and assessment
rules fixed when comparing procedures. Report a one-run demonstration as a
bounded demonstration, not an established causal improvement. Future-evidence
isolation and absence controls need mechanical checks, not promises in prompts.
Using a supplied schema tests representation and acquisition within that schema;
it does not answer the separate original question of fresh ontology construction.
