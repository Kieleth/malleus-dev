## Contract

Claim: exact accepted history and identified action rules determine proposal,
real check outputs, epistemic control, authorization and dispatch eligibility;
execution receipts and independent observations persist in that same history
and reconstruct by replay. Core does not perform the supplier or robot effect.

Smallest observation: the complete selected Shop lifecycle runs from a real
knowledge history. Wrong grant, stale state, fabricated outcome and malformed
second half of the context/proposal transaction refuse without partial append.
Reopen reconstructs exact protocol state while action-only events preserve
domain graph and KCS heads. Receipt success alone never becomes an observation
or accepted knowledge.

Reuse: the twelve finite instructions, complete Assent record contract, existing
hash and control recipes, source/input definitions, real knowledge history,
and its single-writer failure-atomic append. No unrestricted callback, copied
Assent event handler or second ledger is an implementation shortcut.

Classification: the action contract is OPTIONAL_PROFILE; the executor and pure
check producers are REFERENCE_IMPLEMENTATION; Shop and neutral counterexamples
are CONFORMANCE_FIXTURE. Supplier and robotics policy choices/effects remain
ADOPTER_CHOICE. None becomes mandatory for structural-only Malleus adopters.

## Dependency-closed implementation order

1. RED then GREEN: execute the finite operations on exact supplied inputs,
   stage all changes privately and discard on refusal. Bind runtime operand
   shapes and compiled record contracts. Preserve required nonblank semantics
   through an explicit, tested value constraint, with no regex or coercion.
2. RED then GREEN: real TYPE and direct-grant producers, exact implementation
   bytes, and complete selected event programs. No caller-supplied outcomes.
3. RED then GREEN: bind those programs to owning-history input resolution,
   initialization, atomic append and replay. The context/proposal pair has no
   separately committed intermediate state. Default structural behavior and
   standalone Assent keep their existing contracts.
4. Run the full selected Shop lifecycle and negative controls through that
   real boundary. Publish exact consumer calls, artifacts, tests and limits.
   A pure executor passing tests alone does not unblock either consumer.

The implementation remains isolated until the complete boundary is verified.
No main, downstream, paper, supplier store or simulator mutation is included.
No deployment, merge or push is authorized by this local implementation plan.
Other arities, general migration, delivery guarantees, scheduling, scope
hierarchies and cross-language parity remain separate future work. A new
semantic choice beyond the accepted lifecycle returns to Luis; existing
approved meanings do not require field-by-field reapproval.

Pre-action: local Python/data only; no server, endpoint, install or production
incident. No required input default and no fallback. RED precedes each runtime
component. Any discovered divergence receives a failing test and correction
within its owned boundary.
