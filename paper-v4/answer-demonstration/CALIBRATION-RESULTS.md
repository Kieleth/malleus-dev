## What this richer capture establishes, and what it does not

This is a concrete positive control against a universal claim that Sol cannot
populate the fixed ontology or produce relations under the corrected skill.
It does not establish a reproducible effort effect, fresh ontology acquisition,
complete extraction or source truth. The incomplete low arm prevents the
intended semantic comparison under equal full input delivery.

The graph contains four primary-melt CO2 estimates with separate RC2/RC3
subjects, explicit primary-melt stage in subject names, and Rb90/Ba90 proxy
labels in quantity_kind. The frozen query misses all four because it searches
only the observation's own text. An independently executed, read-only diagnostic
using the existing one-hop subject reader recovers all four, adding them to the
generic abstract value. Source-free guard counters remain zero and ledger bytes
unchanged. This is a demonstrated retrieval repair, not a replacement evaluation
or proof that the whole comparison is covered.

The OBS network count and a Zenodo DOI also exist despite empty frozen queries.
The count lacks the query's deployment wording. The DataResource names the
repository but does not express the catalogue role or a deposit relation. These
cases combine narrow matching with incomplete stored role information.

Block accounting reports 92 assertions over 57 blocks and 129 negative
dispositions, with zero untouched blocks. It does not establish completeness.
An independent source probe finds two explicit counterexamples among the
negative dispositions: page:5:block:005 contains a quantitative segment
comparison and geological interpretation; page:7:block:003 contains methodological
results and their justification. Related numbers appear elsewhere, but not all
of those propositions. The fixed surface can represent Claims or typed gaps.
The producer's explanation that all 129 negatives are navigation, figure-only
or reference material is unsupported. This is a capture/classification error,
not evidence that Core certified those blocks as semantically empty. See
[the scope probe](SCOPE-PROBE.md).

[The thirty-question audit](THIRTY-QUESTION-RCA.md) identifies stored values
missed by the read instrument, missing role/qualification fields, missing links
and an inconsistent partial-credit boundary. [The independent scope probe](SCOPE-PROBE.md)

narrowing in the old census capture. Historical scores and populations stay
unchanged. These are specific paper-owned defects and modelling limits, not a
demonstrated missing Core replay or read capability.

Any new paired calibration would need an explicit input-completion stage before
authoring. That is a prospective protocol change, not a retroactive cure for
arm a. The proposed incremental work on existing accepted records remains
separate and requires the author's next decision.

Recommended next order: use the richer ultra graph as a candidate working
baseline, requery it with the existing subject-aware reader and complete an
independent assessment of that view, then target genuine source omissions or
missing links through preservation-checked amendments. This baseline selection
and further execution are proposed, not dispatched. No new full-document
capture, Core rebind or hidden semantic coaching is needed to test retrieval.
