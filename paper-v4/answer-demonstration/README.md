## Query contract

`binding.py` prepares and validates the acceptance-time input manifest without
reading a graph. It freezes all thirty program names, their actual source bytes,
the frozen questions, the accepted surface and the full Core commit. Input drift
or incomplete surface declarations refuse. Its intended-stage marker does not
claim that the producer was actually dispatched later: the coordinating run's
launch log must establish that ordering. This helper is tested but has not been
attached to Fable's prospective runner.

The question source is the exact E-0206 thirty-question file. `pilot.py` refuses
changed question bytes even if IDs remain unchanged. `answers.py` has one named
program per question, with the two paraphrases sharing the corresponding
positive program. No program reads expected outcomes, source text, captures,
previous reviews or an answer key. No numeric answer, record ID, named-site
shortcut or locator is a selector.

The development code has seen historical results, so these are exploratory
programs. Their prospective use requires a method freeze followed by
acceptance-time surface binding before population is visible. A structural
schema mismatch must be reported then; it must not be repaired against later
query results. Fable's type-only coverage arm remains a separate measurement.

Reads use the public graph's query, query_relations and get_node methods.
Programs inspect typed fields and a few declared text fields. Literal matching
is word-bounded and Unicode-normalized. The ordinary lexical variants OBS for
ocean-bottom seismometer, CO2 for carbon dioxide, and sulfur/sulphur are visible
in the code. They are query-language normalization, not inferred domain facts.
Site aliases are not supplied. Name matches select candidates and never prove
what a statement is about.

Quantities are taken from numeric fields, never parsed out of names. Missing
values are not filled; zero remains a value. Bounds, units, scope and modality
remain as stored. Several ranges stay separate. No range is selected because
it agrees with a source answer. Actual subject references are followed without
inventing missing subjects. Relationship paths use only stored edges; programs
may also return descriptions through existing subject references. Cooccurrence
does not become an evidential or causal link.

Outcomes are execution facts:

- CANDIDATES_FOR_REVIEW: the program returned records, not a correctness claim.
- NO_CANDIDATE: this program found none, not proof of source/world absence.
- NOT_EXPRESSIBLE: this program's required type or relation vocabulary is not
  declared. It does not prove every alternative query representation impossible.

Question requirements remain those in the frozen question file. Each selective
result must subsequently be inspected for every requested semantic, including
subject, scope, qualifiers and relevant relationships. Generic labels such as
bounded_quantity never permit a quantity about the wrong substance or site to
satisfy a question. An absent-source control returning candidates triggers
inspection, not an automatic fabrication label.
