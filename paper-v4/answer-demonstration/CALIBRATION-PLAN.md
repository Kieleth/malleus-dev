## Sequence and gates

1. Test exact input closure, unchanged condition, explicit settings and observed
   delivery. Freeze both packets and the executor before either dispatch.
2. Dispatch one fresh producer per arm. Retain every proposed file. Allow at most
   two exact structural returns in the same session, no adequacy coaching.
3. Verify actual model/effort and every bounded input frame in tool outputs.
   Compile, admit, reopen and query using the pinned public runtime. A refusal
   remains the result; no evaluator-authored repair or fallback.
4. Reproduce each admitted history from empty. Inspect typed quantities,
   relations, scope, assertion coverage and natural refusals. Freeze complete
   source-grounded model-assisted reviews of all thirty questions.
   Human ratification remains explicit and pending.
5. Compare against the historical control and each other. Keep generation,
   runtime, query reachability and semantic evaluation separate. No extra sample
   or changed producer condition without another author decision.

If both arms produce useful typed content, the earlier sparse cases are not
reproduced under this packet. If only ultra does, that supports an effort effect
in this pair, not a general model claim. If neither does, the old success is not
repeatable in this pilot despite the held inputs; effort alone is not a sufficient
explanation. One stochastic sample per arm cannot isolate an effect or estimate
its reliability. Runtime checks distinguish proposed omissions from data loss.
