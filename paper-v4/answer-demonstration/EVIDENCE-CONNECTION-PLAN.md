## Four questions, four separate demonstrations

| Question | Evidence required | What does not establish it |
| --- | --- | --- |
| Can the ontology express the meaning? | Show where subjects, qualifications and argumentative roles can be expressed; record a specific missing distinction if they cannot. Compile proposed representations. | A compiling ontology or a high relation count. |
| Is the population faithful? | A separate source reviewer checks every changed value, subject, endpoint and qualification against its context, including contrary passages. | Valid locators, shared words or passing type checks. |
| Does Malleus preserve accepted changes? | Retain the old history, record explicit replacements, reopen and compare old/current states and evidence traces. | A fresh graph that happens to contain the desired rows. |
| Can the reader answer from that state? | Run the same reader before and after; identify the exact newly reachable evidence and unchanged answers. | A new answer written from the PDF, or a retuned reader applied only afterward. |

A SUPPORTS link records an evidential relationship attributed to the source.
It does not turn the paper's hypothesis into verified physical truth. Likewise,
two independent links do not establish that a conclusion follows only from their
conjunction. Preserve that distinction if the passage requires combined evidence.

## Milestones and decisions

### 1. Freeze a source-to-record failure map, with no generation

Use the four cases above. For each, trace source context to captured assertions,
formalization targets, graph properties, admission, replay and query rows. Mark
the first demonstrated loss and any remaining uncertainty. Compare successful
and missing links within run-26 before invoking differences between models.

Separate two possible interventions: resolving what a statement is about, and
representing how statements bear on a claim. A subject name occurring in a
sentence is neither necessary evidence of its meaning nor a semantic guarantee.
The adapter's lexical rule remains in force; a supported alias may satisfy it,
but inventing an alias to pass does not establish the referent.

Deliver a compact case report and a proposed permitted-change list. Each case
ends in a demonstrated loss, already-represented finding, or exact unresolved
reason. This is the next recommended execution step. It launches no model.

### 2. Test one bounded repair after approving that report

Recommended budget: one fresh proposer, one independent source reviewer, at most
one diagnostic return to the proposer and one second review. Keep all attempts.
No selective acceptance of a passing subset or evaluator-written population.
Unsupported asserted meaning withholds the batch; missing coverage is reported.

Supply the selected reading, accepted graph, capture, schema and source-context
cases, without questions, scores, expected values or requested answer edges.
This is a finding-guided repair, not question-blind acquisition. Permit justified
changes to subjects, classifications, qualifications and relations. An additive
ontology change requires a demonstrated unrepresentable distinction first.
Do not repeat the older meaning-repair restriction that protected a potentially
wrong classification while asking the model to repair its meaning.

Before launch, test the selected repair executor on the exact baseline. Reuse
existing public admission/replay and preservation machinery, not a new stack.
Every unaffected record must remain exact, every replacement explicit, every
dependent reference resolved, and the old history available. Test refusals
before writes, dependency closure, and an already-existing link treated as
already represented rather than newly invented. If the historical Core cannot
perform a required change, establish the exact reproducer before requesting it.

Every acknowledged gap gets a supported correction or a specific unresolved
explanation. A generic inventory or NO_CHANGE is not completion. Freeze the reader
and assessment rule before generation. Report source faithfulness, preserved
state and answer changes separately. A covered answer is not a launch condition
or a reason to keep sampling.

### 3. Test the generic procedure in a fresh matched pair

Only after examining the repair result, approve two fresh end-to-end captures:
one existing procedure and one with the single generic procedure change. Both
construct their own ontology and population in one session. Hold model, observed
settings, reading, Core, packs, resource limits and evaluation rules fixed.
If subject resolution and argument capture both need changes, test them in
separate contrasts rather than attributing a combined result to either one.

Neither producer receives the repaired graph, selected cases, questions or prior
answers. Freeze type-based query bindings at ontology acceptance for both.
Use the same reader program and review protocol v3.2. First compare exact field
and path evidence, then report the unchanged thirty-question instrument with
positive questions and controls separate. Preserve regressions as well as gains.

One matched pair is a pilot, not a reliability estimate. This is procedure
transfer on the same article used to develop the intervention, not generalization
to another document or domain. If only the guided repair improves, report that
limit. If a different model replaces the historical Opus condition, report a new
condition and do not attribute its difference from run-26 to the procedure.
