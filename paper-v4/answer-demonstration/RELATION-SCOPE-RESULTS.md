# Relation context fixed in TDD

E-0263 through E-0265. The active answer projection now exposes each relation
endpoint's own one-hop subject context and traces its identity. The query-only
comparison is complete. No graph record, source, ontology or Core code changed.

## Fix and tests

Previously, entity rows expanded subject references but relation endpoints used
the flat projection. A valid quantity could therefore be displayed without its
stored site or stage context. The fix reuses the existing entity-row projection
for both endpoints. Source/target properties stay unchanged; source_subject and
target_subject are separate fields with matching witness IDs. A missing explicit
reference raises an actionable error. No subject is borrowed from the other
endpoint, and traversal remains one hop.

The first RED run had seven failures reproducing missing context, silently
ignored references and unbound review fields. GREEN fixed the projection and
docket. Further RED tests caught a duplicate witness contract in the review
validator; that duplicate was removed. Docket and validator now share one
binding check. Missing context identities, endpoint mismatches and missing
traces refuse. No support or coverage judgment is generated by these checks.

Synthetic tests use arbitrary quantities and distinct sites, not paper answer
values. An AST comparison proves that selectors, constants and all thirty
question programs are unchanged. The active incomplete relation path was
replaced; historical query copies remain frozen as evidence, not runtime fallback.

Final focused harness: 358 passed, two subtests, including seventeen relation-scope
tests. Ruff and formatting pass on the five changed Python files. This is a
paper harness result, not a rerun of the Core suite.
