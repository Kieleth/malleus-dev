## What the audit exposed

The producer marked sixty quantities NO_CHANGE. Several reasons falsely claim
that contextual fields already exist. For example, the average depth uncertainty
has no subject despite a reason claiming a location-method subject. The two LAB
quantities already point to an entity named lithosphere-asthenosphere boundary,
yet the report calls them laboratory experiments. This is failure to use available
context, not missing input delivery, ontology vocabulary or Core replay loss.

The source-supported seafloor reference remains absent from both proposed RC2
depth records. Other missed dependencies include shared assumptions on pre-eruptive
estimates, processing-stage distinctions between uncertainty values, and cited
versus locally measured quantities. Counting every quantity in a report does not
establish that its context was reconciled.

Structural correction also weakened one evidence span. The trace-element assertion
went from a 221-character attempted quotation to the 24-character fragment
`relies on the assumption`. Its full cited block supports the intended assumption;
the fragment alone does not state it. The source bytes were not lost. This shows
why exact location and sufficient evidence content need separate assessment.

## Diagnosis and next proposed cut

The procedure can propagate valid context, but it does not reliably distinguish
source meaning, actual stored fields and inferred correspondence. Full input
delivery, preserved numbers and valid locators do not close that gap. We cannot
infer the model's internal cause or a general failure rate from this one run.

Recommended next cut, not dispatched: explicit source-to-record reconciliation.
Resolve each subject through its stored definition; ground claims of already
represented context in actual record paths; keep summaries separate from specific
estimates; record unresolved correspondences instead of asserting them. Reuse
retained assertion references in the report instead of duplicating quotations
under a second matching rule. Any semantic-feedback revision must be a separately
labelled condition, preserving this result. No current Core capability request
is established.
