# Subject-aware query pass on the frozen Sol graph

The pass recovers one stored quantity, not a complete answer or a missing
relationship. It changes no source, ontology, capture or ledger.

## Method and result

The original thirty query objects reproduced exactly on reopen. The revision
keeps their programs and projections, but candidate matching may also inspect
the name, description and tags of a record's explicit subject. It follows one
hop only. Numeric values stay on the original record; unlinked neighbors and
metadata cannot supply meaning. Ten synthetic guards cover these boundaries.

Only three outputs changed. The other twenty-seven and every relationship path
are identical to the original JSON objects. Candidate-bearing
questions increase from seven to ten. This is retrieval, not source support or
accuracy. The graph and ledger remain unchanged, and the guard records zero
source-file, network and embedding accesses.

| Question | New returned material | Independent review |
|---|---|---|
| Primary-melt quantity | Range, unit and material through its subject | PARTIAL, determination absent |
| Its paraphrase | The same stored row | PARTIAL, determination absent |
| Two-segment comparison | The same material-level row | NONE, segment scope absent |

A fresh Sol reviewer judged the one newly returned witness SUPPORTED against
the selected source and the accepted vocabulary. STATED modality does not say
whether a number was calculated or measured. A range with a material subject
does not establish either side of a segment comparison. The reviewer noted
that isolated range/unit tokens must not be counted as answering that comparison
when the required scope is absent. The existing whole-question rule supports
that distinction; the validator checks consistency, not scientific judgment.

All three changed cases were independently reviewed. This is not a new full
thirty-case review: the other twenty-seven query objects and their prior review
remain unchanged. No human ratification is claimed, and the original complete
Sol review has not been overwritten or relabelled.

## What it establishes

Some answer loss was in the paper query, not Core or capture. The quantity and
its subject were already available through public reads. Other loss remains
in the captured representation: this row lacks the method and site distinctions
needed by the questions, and no SUPPORTS path was supplied. Following subjects
does not infer either. Model, guidance and context differ from the earlier
Opus captures, so this is not evidence that one model is better.

For the manuscript, use the stronger historical run-20/run-21 examples and this
small failure analysis. More Core work is not required to write that result.
An improved population is a separate experiment, not a silent repair here.
