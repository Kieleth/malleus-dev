# What Core can do

The declared capability surface of Malleus Core, with the public entry point for
each one. This file exists because three consumer projects met a limitation on
2026-09-17 and worked around it while Core already carried the capability or the
vocabulary. Luis: "That core has capabilities we're not using in shop is just
plainly wrong, we work on core so that we can use them."

**The rule.** When a limitation is encountered in a consumer project, read this
declaration and use the capability in full before declaring a gap, writing
adopter code, or working around it. A gap is declared only when this declaration
says the capability does not exist, and then it is filed as a Core requirement.

**How to read a row.** `Status` is what `docs/IMPLEMENTATION_STATUS.md` and
`malleus.IMPLEMENTATION_STATUS` say, not what a design document hopes.
`Protocol role` is the closed taxonomy of `docs/PRINCIPLES.md`: a capability
under an `OPTIONAL_PROFILE` binds only when the adopter claims that profile.
`Status document section` is where the boundary statement and its exclusions are
written; `(absent)` there would mean the capability ships and the status
document does not mention it, which is a defect in the status document and not
permission to assume the capability is unsupported. No row carries it today. Backticked identifiers in `Entry point`
are checked for existence by `tests/test_capability_declaration.py`, and every
capability ID in `malleus.IMPLEMENTATION_STATUS` is checked to appear here.

This table says a capability exists and where to call it. It does not say the
capability is right for a case, and `COMMITTED` still means the shape was valid.

## When this table says a capability does not exist

File it as a Core requirement with a pinned reproducer, record the gap in the
consumer's own record, and proceed with the honest partial result. Do not build
an adapter that imitates the missing capability, and do not weaken an existing
check to make the run look complete.

## When this table is wrong

A row that names an entry point which does not import fails
`tests/test_capability_declaration.py`. A capability landing in
`malleus.IMPLEMENTATION_STATUS` and not appearing here fails the same test. A
new `##` section in `docs/IMPLEMENTATION_STATUS.md` fails it too, until someone
reads the section and either declares its capabilities here or records it as
carrying none. Fix the table, not the test.
